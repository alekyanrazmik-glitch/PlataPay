# PlataPay

Статический сайт PlataPay (payoplata.ru) для GitHub Pages — собирается
из оригинального экспорта Тильды в `tilda-original/`.

## Сборка

```bash
node build.mjs
```

Результат в `out/`. Никаких зависимостей не нужно — Node 20+ и всё.

Базовый путь по умолчанию — `/PlataPay` (имя репозитория). Для
кастомного домена передать пустую строку:

```bash
NEXT_PUBLIC_BASE_PATH= node build.mjs
```

## Структура

- `tilda-original/` — оригинальный экспорт из Тильды (источник правды)
- `build.mjs` — скрипт сборки: раскладывает ассеты в `css/`/`js/`/`images/`,
  делает чистые URL (`/`, `/catalog`, `/faq`, `/contacts`),
  патчит навигацию и `<base href>` под GitHub Pages
- `.github/workflows/pages.yml` — деплой на GitHub Pages при пуше в `main`
- `CONTENT.md` — извлечённый контент со старого сайта (для справки)

## SEO-страницы (~101 000 шт., новый дизайн)

Все SEO-страницы собираются в дизайне приложения PlataPay (тёмная
палитра, стеклянная шапка, стикеры категорий, золотые цены, бейджи
«ХИТ»/«−18%»). CSS и JS не инлайнятся: страницы подключают общие
`css/pp-app.css` и `js/pp-app.js` — иначе 100k страниц не влезли бы в
лимит GitHub Pages (1 ГБ на опубликованный сайт).

Ярусы:

- **«Богатые» страницы** (~900): `/oplata-<сервис>/`, `/kak-oplatit-…/`,
  `/…-cena/` и т.д. — контент из `seo/templates.mjs`, каркас
  `seo/layout.mjs`. Модалка тарифов вынесена в общий `js/pp-pricing.js`.
- **Гео-матрица** (~98 000): `/g/<сервис>/oplata-<город>.html` и
  `/g/<сервис>/kupit-<город>.html` — 140 сервисов × 350 городов × 2
  интента. Генератор `seo/geo.mjs`, города с падежами — `seo/cities.mjs`
  (402 города в базе, берутся первые N). Тексты вариативные: интро,
  шаги, FAQ и заголовки выбираются детерминированным хэшем из пулов.
- **Способы оплаты** (1 680): `/oplata-<сервис>-<способ>/` — 12 способов
  (карта Мир/Сбер/Т-Банк/…, СБП, крипта, ЮMoney и т.д.).
- **Хабы городов** (351): `/gorod/` и `/gorod/<город>.html` — списки всех
  сервисов в городе, связывают гео-ярус ссылками.

Общий каркас нового дизайна — `seo/app-shell.mjs` (шапка, hero-панель,
форма заявки, FAQ-аккордеон, футер + весь CSS/JS).

Sitemap — индекс `/sitemap.xml` + шарды в `/sitemaps/` (core + geo по
40 000 URL; лимит формата — 50 000).

Управление объёмом при сборке:

```bash
SEO_GEO=0 node build.mjs            # быстрая сборка без гео-яруса
SEO_GEO_CITIES=8 node build.mjs     # гео-ярус на первых 8 городах
SEO_GEO_CITIES=402 node build.mjs   # все города из базы (~115k страниц)
```

По умолчанию — 350 городов, итого ~100 900 страниц, ~880 МБ. Полная
сборка занимает ~35 секунд.

## Формы

Формы заказа и инвойса отправляют данные в Telegram-бот и в Google
Sheets — токен бота, chat_id и URL Apps Script зашиты в HTML
страниц в `tilda-original/page*.html`. Чтобы поменять — найти
переменные `BOT_TOKEN`, `CHAT_ID`, `SHEETS_URL` и заменить во всех
четырёх страницах.

## Отзывы

Отдельная страница отзывов — `/reviews/` (собирается из
`seo/reviews-page.mjs`, данные затравочных отзывов — в
`seo/reviews-data.mjs`). На ней:

- сводный рейтинг и список отзывов (вшитые + одобренные от посетителей);
- кнопка «Смотреть все отзывы на Avito» (переход сохранён как был);
- форма «Оставить отзыв»: имя, оценка звёздами, текст.

Отзыв посетителя уходит в Google Apps Script (та же таблица, что и
заявки) — на вкладку **«Отзывы»** со статусом «на модерации», плюс
приходит копия в Telegram и на почту. **Чтобы отзыв появился на сайте,
поставьте `да` в колонке «Показывать»** на этой вкладке. Страница
подгружает одобренные отзывы автоматически (JSONP).

Важно: после правки `server/apps-script/Code.gs` нужно **переопубликовать**
Apps Script (Deploy → Manage deployments → New version), иначе приём и
выдача отзывов работать не будут. URL `/exec` при этом не меняется.

Чтобы отзывы публиковались сразу, без модерации, — напишите, переключим.

## Активация кодов — `redeem.payoplata.ru`

Отдельный поддомен, на котором клиент меняет купленный код на подписку.
Дизайн, шапка и футер — общие с основным сайтом, ссылки из шапки ведут
обратно на `payoplata.ru`; для посетителя это один и тот же PlataPay.

| Адрес | Что делает |
|---|---|
| `redeem.payoplata.ru/` | Универсальная: сервис определяется по самому коду |
| `/chatgpt/` | ChatGPT — данные сессии или UID аккаунта |
| `/claude/` | Claude — ключ сессии (`sk-ant-sid…`) или Organization ID |
| `/grok/` | Grok — `session.userId` |
| `/status/` | Состояние кода, ничего не активируя |
| `/restore/` | Подписка не пришла: перепривязка Claude, проверка тарифа ChatGPT |

**Основной сценарий** — отправить клиенту ссылку с уже подставленным
кодом, он сразу попадает на шаг «данные аккаунта»:

```
https://redeem.payoplata.ru/claude/?code=XXXXX-XXXXX-XXXXX
https://redeem.payoplata.ru/?code=XXXXX-XXXXX-XXXXX      # сервис определится сам
```

Код в ссылке только подставляется и проверяется — активация всегда по
кнопке, данные аккаунта вводит сам клиент.

**Демо-режим** для проверки вёрстки без обращения к поставщику: добавьте
`?demo=1`. Ветку выбирает суффикс кода — `-WAIT` (обработка с опросом
статуса), `-ERR` (ошибка аккаунта), `-COOL` (кулдаун), иначе успех.

### Сборка и выкладка

`node build.mjs` собирает два независимых корня:

- `out/` — основной сайт (как и раньше). В нём `/redeem/*` остаются
  заглушками, которые уводят на поддомен с сохранением `?code=` —
  чтобы не побить уже разосланные ссылки;
- `out-redeem/` — сайт активации: шесть страниц, свои `css/`, `js/`,
  `favicon.svg`, `CNAME`, `robots.txt` и `sitemap.xml`.

На VPS:

```bash
bash server/vps/deploy-redeem.sh      # соберёт и выложит в /var/www/platapay-redeem
```

Дальше — `server/vps/nginx-redeem-site.conf.example`: блок для поддомена,
301 со старых `/redeem/*` и прокси `/redeem-api`. Сертификат — `certbot
--nginx -d redeem.payoplata.ru`. Перед первым запуском нужна A-запись
`redeem.payoplata.ru` на тот же IP.

### Смена поставщика API

Адрес поставщика живёт в одном файле — `api-config.js` в корне поддомена:

```js
window.PP_REDEEM_API = "https://redeemgpt.com/api";
window.PP_REDEEM_API_FALLBACK = "/redeem-api";
```

**Менять можно прямо на сервере**, в `/var/www/platapay-redeem/api-config.js`:
пересборка и передеплой не нужны, файл отдаётся с `Cache-Control: no-cache`,
достаточно обновить страницу. `deploy-redeem.sh` сохраняет ваш файл при
обновлении сайта. Если меняете поставщика — поправьте заодно `proxy_pass`
в блоке `/redeem-api` конфига nginx.

Значение по умолчанию задаётся на сборке: `REDEEM_API=… node build.mjs`.
Хост поддомена — `REDEEM_HOST`, каталог сборки — `REDEEM_OUT`.

Запасной адрес нужен на случай закрытого у поставщика CORS: если браузер
заблокирует прямой запрос, скрипт сам переключится на `/redeem-api` —
прокси на своём домене.

### Где что лежит

- `seo/redeem.mjs` — всё: разметка страниц, `REDEEM_CSS`, `REDEEM_JS`
  и словарь `CODE_TEXT` (машинный `code` поставщика → русский текст).
  Тексты ошибок правятся только там.

**Что важно не сломать при правках:**

- формат кода не проверяется намеренно — у разных партий он разный
  (`XXXXX-XXXXX-XXXXX`, `ABCD-EFGH-IJKL`, `bbtgo…`), документация
  поставщика прямо запрещает навязывать свою маску;
- решения принимаются по `code`, а не по тексту `msg` — он китайский;
- `success=false` приходит с HTTP 200, проверять надо оба;
- данные аккаунта уходят из браузера клиента прямо поставщику и на
  серверы PlataPay не попадают — это обещано на самих страницах.
